# Підготовка до захисту лабораторної №2

**Тема:** Інвертований індекс: словники, хешування та пам'ять.

## Приблизний 5-хвилинний виступ

У другій лабораторній роботі я продовжив розробку пошукової системи findex
на базі вже створеного генератора документів і токенізатора з лаби №1.

Інвертований індекс — це словник, у якому ключем є термін, а значенням —
список постінгів. Кожен постінг зберігає числовий ID документа і частоту
терміна в ньому. Індекс будую за один прохід корпусу: читаю документ,
підраховую його слова через Counter і додаю записи в defaultdict.
Списки постінгів відсортовані за ID, оскільки IDs зростають під час обходу.

Для результатів пошуку зберігаю також довжину кожного документа,
відносний шлях і заголовок. Записи Posting і DocMeta реалізовано як
незмінні dataclass із slots. Для майбутнього пошуку фраз є режим
збереження позицій токенів.

Реалізував Boolean-пошук AND, OR, NOT. Для merge використовуються
два вказівники на відсортованих постінгах, а для альтернативного
рушія — set. Запити з двох слів трактуються як AND. Через аргумент
--engine можна переключити реалізацію.

Щоб не будувати індекс щоразу, реалізував pickle і JSON. Особливість
pickle — його не можна безпечно завантажувати з недовіреного джерела,
оскільки десеріалізація може виконати сторонній код.

Виконав заміри трьох представлень постінгів: звичайний dataclass,
dataclass із slots та array('I'). У контрольному тесті на локальному
демокорпусі з 1000 документів пік пам'яті становив відповідно
5.361, 3.617 і 1.110 MiB. У компактному масиві не створюються окремі
Python-об'єкти для кожної пари чисел. Також порівняв швидкість
merge/set і save/load двох форматів.

Продовження лабораторної знаходиться у тому самому репозиторії,
а версію для здачі потрібно позначити тегом lab-02.

## Reflection: короткі відповіді

**1. Що таке хеш-таблиця?** Ключ обробляється функцією hash(),
результат допомагає обрати слот. Якщо різні ключі потрапляють в
один слот, виникає колізія. CPython використовує відкриту адресацію
та пошук іншого слота. Пошук у середньому O(1).

**2. Контракт __hash__ та __eq__?** Якщо a == b, то hash(a) має дорівнювати
hash(b). Якщо змінити ключ після вставки так, що його хеш зміниться,
словник може не знайти цей ключ, бо шукає за новим хешем.

**3. Чому списки не хешуються?** Список змінний, а хеш ключа повинен
залишатися стабільним. Кортеж хешується лише тоді, коли всі його
елементи хешовані. Кортеж (1, [2]) не хешується через вкладений список.

**4. Для чого frozen=True?** Забороняє присвоювати полям нові значення,
а для класу з хешованими полями dataclass генерує сумісні методи
__eq__ та __hash__. Якщо власноруч перевизначити __eq__ і не
визначити __hash__, Python зазвичай робить об'єкт нехешованим.

**5. Як працюють slots?** Замість окремого __dict__ на кожен об'єкт
його поля зберігаються у фіксованих слотах. Економиться пам'ять,
але не можна довільно додавати нові атрибути.

**6. Чому array('I') менший?** Кожна пара (doc_id, tf) — два беззнакових
32-бітних цілі числа, тобто 8 байтів даних без окремих Python int
і Posting для кожної пари. Словник термінів і самі масиви мають накладні
витрати, тому загальна пам'ять більша.

**7. Merge і set?** AND/OR із двома вказівниками має складність
O(len(A)+len(B)); множини швидкі за рахунок хешування, але вимагають
додаткової пам'яті для копій. Порівняння залежить від частот та
розміру постінгів; конкретні числа беремо з бенчмарку свого комп'ютера.

**8. Чому pickle.load небезпечний?** Формат pickle допускає інструкції,
які при завантаженні можуть викликати Python-об'єкти або функції.
Недовірений індекс може виконати шкідливий код. Завантажувати тільки
власні файли або використовувати JSON з валідацією.
